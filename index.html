Introducción

Este plan de pruebas describe la estrategia, los recursos y el cronograma para las actividades de prueba del sistema de gestión de biblioteca. El objetivo es garantizar que el software cumpla con los requerimientos establecidos y funcione correctamente antes de su implementación en producción.

Estrategia y criterios de pruebas

Cobertura ≥ 80%

Pruebas de integración

Validar comunicación entre módulos y servicios

Comunicación validada

Pruebas de sistema

Validar funcionalidades completas end-to-end

Flujos completos

Pruebas de aceptación

Validar con casos de uso reales y stakeholders

Aprobación del cliente

Criterios de aceptación

  • Todas las pruebas unitarias deben pasar
  • Cobertura de código ≥ 80%
  • Todas las funcionalidades críticas probadas
  • Rendimiento dentro de parámetros establecidos
  • Aprobación del equipo de calidad y stakeholders

Requisitos de software

  • Sistema operativo: Windows 10/11, Linux Ubuntu 20.04+
  • Java: JDK 17 o superior
  • Base de datos: MySQL 8.0 o PostgreSQL 14
  • Servidor de aplicaciones: Apache Tomcat 9+
  • Herramientas de build: Maven 3.6+
  • Control de versiones: Git

Identificación de riesgos y contingencias

Cambios en requerimientos

Probabilidad: Alta

Impacto: Medio

Mitigación: Comunicación constante con stakeholders

Falta de datos de prueba

Probabilidad: Media

Impacto: Alto

Mitigación: Crear scripts de datos de prueba

Problemas de entorno

Probabilidad: Media

Impacto: Alto

Mitigación: Documentación detallada de configuración

Tiempo insuficiente

Probabilidad: Media

Impacto: Alto

Mitigación: Priorización de pruebas críticas

Plan de contingencias

  • Reserva de tiempo: 20% adicional en cronograma
  • Entornos alternativos: Configuración de entornos de respaldo
  • Equipo de soporte: Disponibilidad para problemas críticos
  • Backup de datos: Respaldos regulares de datos de prueba
